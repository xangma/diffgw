# First campaign producing our own BBH numerical-relativity data

Read-only planning review, 2026-09-12. No software was installed, jobs submitted,
simulation data generated, or calibration coefficients fitted. No GPL/LAL
implementation was inspected. This proposal concerns **our simulation outputs
generated with existing NR software**; it does not constitute our own NR solver.

SpECTRE is a credible first candidate. Its pinned
[v2026.09.05 license](https://raw.githubusercontent.com/sxs-collaboration/spectre/v2026.09.05/LICENSE.txt)
is MIT. The separately used orbital-parameter/eccentricity package
[SimulationSupport](https://raw.githubusercontent.com/sxs-collaboration/SimulationSupport/50e6a22084d955f9d0bbd4285a11c7c05e4d3a04/LICENSE.txt)
is also MIT. However, SpECTRE's required dependencies include
[GSL](https://spectre-code.org/installation.html), which GNU identifies as
[GPL software](https://www.gnu.org/software/gsl/). Therefore the complete build
cannot be described as an entirely permissively licensed stack. Preserve its
dependency/license manifest separately from torchwave's source and data records;
redistribution of a solver environment needs its own concrete license review.

The authors demonstrate an equal-mass, nonspinning binary through roughly 18
orbits, merger, ringdown, and Cauchy-characteristic extraction (CCE), at three
resolutions. Their initial separation is 15.366 M. Their example used an outer
boundary at 600 M; they discuss moving it to 1500 M to reduce boundary effects.
Reported evolution costs on 560 Cascade Lake cores were 58,000 / 71,000 /
117,000 core-hours, approximately 104 / 127 / 209 wall-hours. These are historical
measurements for that experiment, **not runtime forecasts for our pilot**.
[Primary demonstration, Sec. 3.3](https://arxiv.org/html/2410.00265v2).

## Build and execution prerequisites

The installation guide lists a supported C++ compiler (GCC >=10, Clang >=13, or
Apple Clang >=13), Fortran, CMake >=3.18, Python >=3.10, Boost >=1.60, HDF5,
BLAS/LAPACK, GSL, and Charm++ >=7, with version 8 preferred. Use a matching MPI
Charm++ backend on a cluster. Docker and Spack recipes exist, but the guide marks
Spack support unstable. Pin the SpECTRE release, all dependency versions, compiler
flags, MPI runtime, and environment digest before generating data.
[Installation guide](https://spectre-code.org/installation.html).

Build and validate the documented `SolveXcts`, `EvolveGhBinaryBlackHole`,
`EvolveGhSingleBlackHole`, and `CharacteristicExtract` executables plus the Python
CLI/bindings. The current CLI identifies itself as 2026.09.05; online documentation
is rolling, so validate each installed command's help and generated input against
the pinned build before scheduling anything.
[CLI and BBH pipeline](https://spectre-code.org/py/cli.html),
[CCE tutorial](https://spectre-code.org/tutorial_cce.html).

No numerical RAM, storage, or queue allocation is justified for our hardware yet.
Measure peak memory, output growth, throughput, and restart behavior in the short
eccentricity-control evolution before allocating the three full runs. Neither a
laptop feasibility claim nor GPU acceleration is assumed.

## Proposed pilot worksheet

These are intended physical/numerical settings, not a validated executable YAML.
All tolerances below are proposed pilot choices and can be tightened after the
short-run measurements.

| Item | Proposed setting |
| --- | --- |
| Units and component masses | G=c=M=1; target horizon masses 0.5 and 0.5; q=1 |
| Spins | Both target dimensionless spin vectors (0, 0, 0) |
| Initial coordinate separation | 15.366 M, following the demonstrated case |
| Eccentricity | Target zero; first acceptance tolerance 1e-3 |
| Initial-data controls | Enable mass/spin control and eccentricity control |
| Initial-data resolution | h-refinement 1, polynomial order 9; verify with order 11 |
| Evolution convergence | Identical converged physical setup at Lev0, Lev1, Lev2 |
| Boundary/extraction proposal | Outer boundary 1500 M; worldtubes 200, 300, 400 M |
| CCE convergence proposal | Start angular Lmax=20, filter=18; repeat at 24/22 and tighter time tolerance |
| Retained waveform modes | At least all available strain modes with 2 <= ell <= 4 |

The initial-data API explicitly supports target masses/spins, `MassRatio`,
`Eccentricity`, `EccentricityAbsoluteTolerance`, and `EvolutionLev` through
`generate_id`. Set `control=True`, `evolve=True`, and `eccentricity_control=True`
with a dedicated `pipeline_dir`. Its documented initial orbital guesses are
computed by SimulationSupport; retain the values and each subsequent correction
generated by our own control iterations. No catalog waveform or previously fitted
orbital parameters are required.
[Initial-data API](https://spectre-code.org/py/_autosummary/spectre.Pipelines.Bbh.InitialData.html).

## Workflow and acceptance

1. Generate XCTS initial data, drive horizon masses/spins to the targets, then run
   short Lev1 evolutions for eccentricity control. Fit after junk radiation over
   roughly two to three orbits; repeat with a shifted fit window to check that
   the chosen 1e-3 threshold is meaningful. Save every iteration. The documented
   control command can branch multiple resolution levels after convergence.
   [Control workflow](https://spectre-code.org/py/cli.html#eccentricity-control).
2. Freeze the converged physical initial-data parameters and evolve all three
   levels through common-horizon formation. Inspect constraints, horizon
   quantities, control-system errors, excision behavior, and checkpoint restarts.
   The inspiral API exposes `continue_with_ringdown`; the ringdown pipeline maps
   the inspiral data to a single-hole evolution. Verify this transition in the
   pinned build before unattended runs.
   [Inspiral API](https://spectre-code.org/py/_autosummary/spectre.Pipelines.Bbh.Inspiral.html),
   [Ringdown API](https://spectre-code.org/py/_autosummary/spectre.Pipelines.Bbh.Ringdown.html).
3. Run CCE on our retained inspiral and ringdown Bondi-Sachs worldtube files.
   The pipeline combines the segments and expects the documented radius naming
   convention, `RXXXX.h5`. Repeat the extraction at the proposed radii and CCE
   resolutions; check sensitivity to initial null-surface transients and time
   stepping. Use a recorded asymptotic frame/BMS prescription consistently.
   [CCE API](https://spectre-code.org/py/_autosummary/spectre.Pipelines.Bbh.Cce.html),
   [CCE numerical settings](https://spectre-code.org/tutorial_cce.html).
4. Compare successive resolutions after one fixed time/phase alignment over an
   explicitly chosen inspiral interval. Report complex h22 differences, amplitude
   and phase errors where amplitude is appreciable, remnant mass/spin convergence,
   extraction errors, and the expected suppression of odd-m modes for this
   symmetric configuration. Do not assume a power-law convergence order for the
   spectral/discontinuous-Galerkin scheme. The pilot succeeds when these error
   sources are measured and controlled; a waveform accuracy threshold for model
   calibration still needs to be chosen.
5. Archive source/dependency commits and licenses, generated inputs, numerical
   settings, orbital-control history, logs, resource measurements, checkpoints,
   horizon data, worldtube data, raw/final modes, extraction/frame recipes, and
   SHA-256 manifests. Each later coefficient must trace to these owned run
   outputs and a reproducible fitting script. Preserve raw data separately from
   any aligned or hybridized waveform products.

Before launch, select the host, queue, CPU/RAM allocation, storage quota,
wall-time/checkpoint policy, and budget. Each actual job record must include host,
cwd, exact command, scheduler ID/PID, log path, next check, and stop command. There
are no active jobs from this review.

One q=1 nonspinning point establishes a reproducible convergence workflow. It
cannot replace a fit over mass ratio, aligned/precessing spins, or higher-mode
behavior. A subsequent campaign needs an agreed parameter domain, waveform error
target, training/validation split, hybridization prescription, and data-release
policy. Those choices and a compute allocation remain open; no completed
independent BBH calibration is claimed here.
